## 本期关注：Tibo Day 8 预告重置，Meta 加入长任务竞争

AI 能不能持续把工作做完，正在同时受到三件事影响：可用额度、跨步骤记忆，以及行动权限。今天，Tibo 再次预告 reset；Meta 发布面向长任务的新模型；Anthropic 则用受控实验提醒，更强的持续执行能力也需要更清楚的安全边界。

**先看三件事：**

- **Tibo Day 8 是一次新的 reset 预告。** 北京时间今早 09:03 发帖，并称全局重置将在其所写的“EOD PST time”前落地；尚不能据此确认所有账户已到账。
- **Meta 发布 Muse Wonder 与 Wonder Full。** 前者进入 API 和 Muse Code，后者限特定 Muse Code 订阅；选型时要一起看价格和内容是否用于训练。
- **Anthropic 研究小模型自复制风险。** 实验显示若干关键步骤已可完成，但研究使用简化、受控环境，不能写成真实世界已有完整失控复制体。

## 01 · Tibo 最新：Day 8 再次预告 reset，额度规则仍在讨论

### 这次说了什么

**10 月 13 日 09:03，北京时间（01:03 UTC）**，Tibo（@thsottiaux）发布“Day 8/ Reset”，并在同一分钟的本人跟帖中写道：“Global reset landing by EOD PST time. Enjoy”。这是一条新的全局重置预告，区别于第一期记录的此前重置完成声明。[Day 8 主帖](https://x.com/thsottiaux/status/2109812216212099456) · [本人时间说明](https://x.com/thsottiaux/status/2109812360596865224)

两条短帖没有逐项列出适用套餐、涉及哪些额度窗口或账户生效进度。本期保留其 **EOD PST time** 的原始截止措辞，不把它换成确定的北京时间到账时刻；也未进入账户核实余额。读到这条消息，能够确定的是 Tibo 作出了预告，不能据此认定所有用户的额度已经恢复。

### 投票有了结果，也有了本人的新反馈

10 月 11 日发起、面向 Pro 用户的投票已结束，公开页面显示 **240,643 票**：33.2% 选择“恢复 5 小时限额、周用量翻倍”，37.8% 选择“没有 5 小时限额、维持原用量”，另有 29% 选择只看结果。**这是一次自愿参与的 X 投票，不能代表所有 Pro 用户，也不能把 37.8% 写成全体投票者的多数。** [投票原帖与最终结果](https://x.com/thsottiaux/status/2109152716954222849)

在第一期核查截止之后，Tibo 于 **10 月 12 日 08:21，北京时间**发帖称结果让他困惑：他原以为 Pro 100 美元、Pro 200 美元、Pro 500 美元用户会更偏向以恢复 5 小时限额换取两倍周用量，以平滑需求。这里依然是产品取舍的讨论，没有宣布该方案已经实施。[本人反馈](https://x.com/thsottiaux/status/2109439315570999598)

**本期解读。** 额度总量和可连续工作的时间，是两种不同的价值。集中赶工的人可能更在乎不被短周期限额打断；能错峰使用的人可能更看重一周的总量。一次 reset 若按预告落地，会缓解眼前的用量压力，但不足以回答长期套餐如何设计。真正值得跟进的是稳定规则，而不是把临时重置计入固定可用预算。

作为背景，10 月 12 日的 Day 7 已宣布 GPT‑6.1 Sol 在 Codex 与 Work 的默认上下文由 272k 提至 500k，并称从订阅额度扣用量时不收长上下文费用。那项变化针对上下文与收费；Day 8 这两条短帖没有宣布新模型或更大的上下文。[Day 7 原帖](https://x.com/thsottiaux/status/2109430343346581527) · [订阅费用说明](https://x.com/thsottiaux/status/2109430894604026039)

## 02 · Meta Muse Wonder：长任务多了一个选项，先看开放条件

Meta 在 **10 月 12 日**发布 **Muse Wonder 与 Muse Wonder Full**。官方重点介绍两项能力：Active Memory 跨对话保留并检索相关信息，Active Focus 在复杂任务中继续尝试、处理阻碍并根据新信息调整。这些是厂商公布的能力描述，本期没有独立复现其效果或确认性能排名。[Meta 发布公告](https://research.meta.ai/blog/muse-wonder)

对准备试用的人，开放条件比“最强”标签更有用：

- **Muse Wonder**：模型标识为 muse-wonder-1.0，可通过 Meta Model API 和 Muse Code 使用；官方文档标为预览，上下文窗口为 **1,048,576 token**。[入门文档](https://dev.meta.ai/docs/overview)
- **Muse Wonder Full**：目前不在按量付费 API 中提供，只在 Muse Code 的 **Power Usage 与 Maximum Usage** 订阅中开放。将 Wonder 的推理力度调至 max，不会切换成 Full。[型号与开放范围](https://dev.meta.ai/docs/models)
- **API 价格**：Wonder 的 Standard 模式按每百万 token 计，普通输入 **4 美元**、缓存输入 **0.20 美元**、输出 **20 美元**；文档明确没有长上下文加价，网页搜索等工具另收费。价格不能直接套用于 Full 订阅。[价格文档](https://dev.meta.ai/docs/pricing-rate-limits)

还有一个值得在试用前看清的条件：**Muse Code 订阅默认开启 Contributor 模式**，以允许 Meta 将提示、代码、文件、上下文及模型回复用于训练，换取更多用量；用户可关闭，关闭后未来内容不再用于训练，除非再次开启。Wonder 和 Full 在包含它们的订阅套餐中均可使用 Standard 或 Contributor 模式；Wonder 的按量付费 API 则只提供 Standard 模式。套餐权益与可用性可能随地区不同。[订阅与内容使用说明](https://dev.meta.ai/docs/muse-code/subscriptions) · [模型文档](https://dev.meta.ai/docs/models)

**本期解读。** 与 Codex 的上下文和额度更新放在一起看，长任务竞争已经延伸到“能记住多少、能持续多久、允许使用哪些数据”。团队比较工具时，应选一项需要跨文件修改、反复验证的真实任务，同时记录人工接管、返工与总成本；涉及客户资料或私有代码，还要先核对数据使用设置。更大的窗口和更多额度，只有转化成可靠交付才有价值。

## 03 · Anthropic：持续执行能力的另一面，需要受控验证

Anthropic Frontier Red Team 在 **10 月 12 日**发布自复制风险研究。作者报告，一个 9B 模型在测试的 9 类硬件中，有 8 类成功搭建推理服务；另一些小模型虽能完成若干单步任务，仍难以可靠串起完整链条。[研究原文](https://www.anthropic.com/research/self-replicating-ai)

实验边界尤其重要：端到端测试在隔离环境中进行，并大幅简化了入侵环节；较强模型在独立推理服务器上运行，目标设备部署的是用于统一比较的小模型。因此，这不是“模型已经在真实互联网自主复制自身权重”的证明。作者也明确表示尚未得到完整的失控复制体；关于小模型可能在年内达到相应能力的判断，是趋势外推而非已验证结果。

**本期解读。** 产品希望代理更能坚持、适应陌生环境，安全研究则要检验同类能力会如何越过授权边界。两者应一起看。对部署者，除了检查任务完成率，还应保留最小权限、网络隔离、操作记录和可中止机制。本期只讨论研究结论与限制，没有运行这些实验。

## 接下来值得追问

1. **Tibo 的 Day 8 reset：** 后续是否明确完成、适用套餐和额度范围？短周期限额与周用量是否会形成正式新政策？
2. **Muse Wonder：** 在相同质量要求下，长任务的返工、人工接管与总成本表现如何？跨对话记忆能否被用户检查和纠正？
3. **代理安全：** 在更接近真实环境、权限受限的测试里，持续执行能力还能完成多少工作，哪些行为需要人接管？
